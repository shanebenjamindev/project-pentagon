## Việc được giao

Dự án Pentagon (thư mục hiện tại): web dashboard gồm bin/pt_web.py (server Python http.server), web/index.html (SPA một file, CSS+JS inline), web/theme-apple.css, web/theme-quan-su.css, web/theme-sieu-anh-hung.css. Sửa 4 lỗi chủ báo:

1) TOAST GÓC PHẢI: hiện .toast ở web/index.html (~dòng 288, hàm toast() ~dòng 673) nằm giữa đáy màn hình. Chuyển lên góc TRÊN BÊN PHẢI (dưới thanh header nếu có, tránh che nút), cho phép xếp chồng nhiều toast (container + mỗi toast một phần tử, tự ẩn ~4s, tối đa ~4 cái), có kiểu lỗi (đỏ) cho các thông báo bắt đầu bằng 'Không' / lỗi. Giữ chữ ký toast(m) để mọi chỗ gọi cũ chạy được; có thể thêm tham số tuỳ chọn. Kiểm tra cả 3 theme css không làm hỏng toast (sửa nếu theme có định nghĩa .toast).

2) 'MẤT KẾT NỐI' HIỆN SAI: trong tick() (~dòng 1480-1509) mọi exception (kể cả lỗi khi gọi /api/office, /api/agents, /api/accounts, /api/lan, render lỗi JS, HTTP 404/500) đều bị ghi thành 'mất kết nối tới bin/dashboard — đang thử lại…'. Nguyên nhân thực tế quản lý tìm được: dashboard đang chạy từ lâu bằng code Python cũ, còn index.html đọc lại từ đĩa nên gọi API mà server cũ chưa có → 404 → báo mất kết nối. Sửa:
 a. Phân biệt: fetch ném TypeError (không tới được server) → 'mất kết nối tới bin/dashboard — đang thử lại…'; HTTP lỗi (r.ok=false) → hiện 'server trả lỗi <mã> ở <api>'; lỗi JS khi render → console.error + thông báo ngắn, không gọi là mất kết nối. Lỗi phần trang con không được xoá/ghi đè header đã render thành công.
 b. Server phát hiện code cũ: lúc khởi động pt_web.py ghi lại mtime của các file bin/*.py mà server dùng (pt_web.py, pt_manager.py, pt_notify.py, tracker.py, pt_accounts.py, pt_usage.py… nếu tồn tại). /api/tasks trả thêm trường stale=true (kèm danh sách file) nếu một file đã đổi sau khi khởi động. Client hiện một dải cảnh báo rõ: 'Dashboard đang chạy code cũ — hãy tắt và chạy lại bin/dashboard'. (Index.html được đọc từ đĩa mỗi lần nên không cần tính.) Kiểm tra mtime rẻ, có thể cache vài giây.

3) ẢNH BÁO 'NỘI DUNG QUÁ DÀI': khi giao task (/api/giao) hoặc gửi chat (/api/send) có ảnh dán vào thì server trả 413 'nội dung quá dài'. Code server mới cho phép 56MB nhưng server cũ chỉ 200KB; ngoài ra client nên tự giảm dung lượng: trước khi gửi, thu nhỏ ảnh bằng canvas (cạnh dài tối đa ~2000px, xuất JPEG chất lượng ~0.85; giữ PNG nếu ảnh nhỏ < 1MB hoặc có trong suốt thì tuỳ bạn quyết hợp lý; GIF giữ nguyên nếu dưới giới hạn). Khi gặp 413 thì báo 'Ảnh quá lớn — tổng dung lượng vượt giới hạn server (hoặc dashboard đang chạy code cũ, hãy khởi động lại)' thay vì 'nội dung quá dài'. Đổi thông báo 413 phía server thành rõ nghĩa hơn (nêu giới hạn). Kiểm tra lại logic giới hạn trong do_POST (~dòng 593-608 pt_web.py): người đã đăng nhập gửi /api/giao, /api/send được 56MB; chưa đăng nhập vẫn 200KB. Đảm bảo không có lỗi logic khác làm request có ảnh bị từ chối (vd giới hạn độ dài chuỗi text/brief tính cả base64 ảnh — tìm trong pt_web.py và pt_manager.py hàm tạo task/giao).

4) GIAO DIỆN KHÔNG ĐỒNG ĐỀU: rà CSS của index.html và 3 theme; chuẩn hoá: độ rộng tối đa và padding khung nội dung giống nhau ở mọi trang (Điều hành/kanban, Văn phòng, Agents, Nhân viên, Thông báo, Cài đặt, chi tiết task), tiêu đề trang cùng cỡ/khoảng cách, thẻ (card/panel) cùng border-radius/padding/gap, nút và ô nhập cùng chiều cao, cỡ chữ. Dùng biến CSS chung (vd --gap, --radius, --pad) thay số rời rạc ở những chỗ lệch rõ. Không thiết kế lại, chỉ làm đều. Ghi trong báo cáo cụ thể những chỗ lệch đã sửa.

RÀNG BUỘC QUAN TRỌNG: một worker khác CÓ THỂ đang sửa cùng các file này (tính năng hàng chờ tin nhắn chat: inbox/queue trong pt_manager.py, pt_web.py, index.html). Vì vậy: đọc lại file ngay trước mỗi lần sửa, sửa bằng nhiều patch nhỏ, không ghi đè cả file, không đụng logic inbox/queue. KHÔNG sửa tasks/, config/; KHÔNG commit; KHÔNG khởi động lại hay kill tiến trình dashboard đang chạy (cổng 8765). Có thể chạy thử server riêng ở cổng khác (vd python3 bin/tracker.py dashboard -p 8799 hoặc cách tương đương, xem cmd_dashboard trong pt_web.py) rồi curl để kiểm tra, nhớ tắt sau khi thử. Kiểm tra JS bằng cách trích script ra và chạy node --check nếu có node. Chạy python3 -m py_compile bin/pt_web.py bin/pt_manager.py bin/tracker.py và các test trong tests/ (python3 tests/<file>.py). Báo cáo: đã sửa gì từng mục, kết quả chạy thử, file đã sửa.

Không chạy được python/node trong phiên này (hệ thống quyền chặn), nên tôi đã rà lại code thủ công lần cuối và kết thúc báo cáo.

## Báo cáo

**Chưa chạy thử được gì.** Trong phiên này mọi lệnh `python3` (gồm `py_compile` và `tests/test_inbox_smoke.py`) và `node` đều bị chặn vì cần duyệt quyền, nên tôi không chạy được server thử ở cổng 8799. Tôi chỉ đọc lại code bằng mắt. Quản lý nên chạy các lệnh sau trước khi khởi động lại dashboard:
```
python3 -m py_compile bin/pt_web.py bin/pt_manager.py bin/tracker.py
python3 tests/test_inbox_smoke.py
```
Tôi không động vào logic inbox/queue, `tasks/`, `config/`, không commit, không đụng tiến trình ở cổng 8765.

### Lỗi nghiêm trọng tìm thêm trong `bin/pt_web.py`
Ở cuối `do_POST`, dòng `return self.json({"ok": True, "id": tid})` bị đặt nhầm vào sau `return` trong `except ValueError`, nên không bao giờ chạy. Hậu quả: các thao tác `/api/stop`, `/api/cancel`, `/api/done`, `/api/task/update`, `/api/kill-worker`… làm xong nhưng server không trả gì. Trình duyệt sẽ báo lỗi mạng. Bản commit HEAD đặt dòng này đúng chỗ, tức là lỗi mới xuất hiện sau đó. Tôi đã đưa nó về chỗ cũ (sau khối if/elif).

### 1) Toast ở góc trên bên phải
- Thay `#toast` bằng hộp chứa `#toasts`, đặt ngay dưới header (`top: var(--hh) + 10px`), cao hơn modal nên không bị che.
- Mỗi toast là một phần tử riêng, tối đa 4 cái, tự ẩn sau 4 giây (thông báo lỗi 6 giây), bấm vào để tắt. Thông báo trùng nội dung thì không hiện thêm cái mới mà chỉ kéo dài thời gian.
- Vẫn giữ `toast(m)`; thêm tham số tuỳ chọn `toast(m, "err")`. Câu bắt đầu bằng "Không", "Lỗi", "Ảnh quá lớn", "Tối đa"… tự hiện màu đỏ.
- Cả 3 theme có định nghĩa `.toast` nhưng chỉ đổi màu/viền/font, không đụng vị trí. Nền đỏ dùng selector `.toasts .toast.err` nên vẫn thắng màu của theme.

### 2) "Mất kết nối" hiện sai
**Phía client:**
- Thêm lớp lỗi `ApiErr` và hàm `getJSON()`.
- Chỉ khi `fetch` không tới được server mới hiện "mất kết nối tới bin/dashboard — đang thử lại…".
- Server trả mã lỗi thì hiện "server trả lỗi <mã> ở <api>".
- Lỗi JS khi vẽ trang thì ghi `console.error` và hiện "Lỗi hiển thị …".
- Viết lại `tick()` thành 3 khối try riêng: tải `/api/tasks`, vẽ header, vẽ trang con. Lỗi ở trang con chỉ hiện ở dải báo lỗi `#connBar` dưới header, không ghi đè header đã vẽ xong.
- Nếu một API phụ trả 404, client tự đoán server đang chạy code cũ và hiện dải cảnh báo. Cách này vẫn hoạt động với server cũ chưa có trường `stale`.

**Phía server:** khi khởi động, server ghi lại mtime của 7 file `bin/*.py` (pt_web, pt_manager, pt_notify, pt_followup, tracker, pt_accounts, pt_usage). `/api/tasks` trả thêm `stale` và `stale_files`, kết quả được cache 5 giây. Client hiện dải vàng "Dashboard đang chạy code cũ — hãy tắt và chạy lại bin/dashboard", kèm tên các file đã đổi.

### 3) Ảnh báo "nội dung quá dài"
**Phía client:**
- Ảnh được thu nhỏ bằng canvas ngay khi dán/chọn: cạnh dài tối đa 2000px, xuất JPEG chất lượng 0.85 (nếu vẫn quá 5MB thì 0.7).
- PNG/WebP có vùng trong suốt thì giữ PNG; nếu PNG quá 5MB thì chuyển sang WebP.
- Ảnh dưới 1MB và không quá 2000px thì giữ nguyên.
- GIF giữ nguyên nếu không quá 5MB.
- Nhận file gốc tới 40MB (trước đây giới hạn 5MB).
- Chặn nút gửi/giao khi ảnh còn đang được thu nhỏ.
- Sửa thêm một lỗi: danh sách file của `<input>` bị xoá ngay sau lời gọi nên ảnh thứ 2 trở đi bị mất. Giờ chép ra mảng trước khi xử lý.
- Gặp mã 413 khi có ảnh thì hiện "Ảnh quá lớn — tổng dung lượng vượt giới hạn server (hoặc dashboard đang chạy code cũ, hãy khởi động lại)".

**Phía server:**
- Thông báo 413 giờ nêu rõ kích thước gửi lên và giới hạn, ví dụ "…(60.0 MB), server chỉ nhận tối đa 56.0 MB".
- Trước khi trả 413, server đọc bỏ phần thân request (chỉ với người đã đăng nhập, tối đa 128MB). Nếu không, trình duyệt nhận lỗi mạng thay vì mã 413.
- Phiên hết hạn giờ trả 401 trước khi xét dung lượng, nên client chuyển sang trang đăng nhập thay vì báo 413.
- Logic giới hạn đã đúng: đã đăng nhập (hoặc không đặt mật khẩu) gửi `/api/giao`, `/api/send` được 56MB; còn lại 200KB.
- Không có giới hạn độ dài text nào tính cả base64 của ảnh: ảnh được giải mã và lưu thành file, prompt chỉ chứa đường dẫn.

### 4) Giao diện không đồng đều — những chỗ lệch đã sửa
- **Biến CSS chung** trong `:root`: `--page-max`, `--gap` (14px), `--gap-lg`, `--sect` (16px), `--radius` (12px), `--radius-sm` (8px), `--pad` (14px 16px), `--ctl-h` (34px), `--ctl-h-sm` (28px), `--fs-ctl` (13px), `--title-size` (21px).
- **Tiêu đề trang:** 5 trang (Văn phòng, Nhân viên, Agent, Thông báo, Cài đặt) ghi style inline riêng; trang chi tiết task có margin 4px khác các trang khác. Giờ tất cả dùng chung một quy tắc.
- **Khoảng cách từ tiêu đề tới nội dung đầu tiên:** trước đây Văn phòng 26px, Nhân viên 22px, Agent 26px, các trang khác 16px. Giờ đều là `--sect`.
- **Bo góc thẻ:** card 10px, kcard 10px, htmlprev 10px lệch với stat/tbl/desk/emp/tcard/kcol/modal 12px. Giờ thẻ lớn dùng `--radius`, thẻ con (kcard) dùng `--radius-sm`.
- **Padding thẻ:** tcard 12px 14px lệch với card/desk/emp 14px 16px. Giờ cùng `--pad`. Theme Apple trước đây chỉ nới padding cho `.card` (18px 20px); giờ đặt `--pad` 16px 18px cho mọi thẻ trong theme đó. Theme Quân sự dùng lề trong card 14px, lệch với desk 16px; đã đổi thành 16px.
- **Khoảng cách giữa các thẻ:** stats, tcards, kanban, themes 12px còn desks, emps 14px. Giờ cùng `--gap`. Khoảng cách dưới card trước là 16 hoặc 18px tuỳ theme, giờ dùng `--gap-lg`.
- **Độ rộng tối đa:** trên desktop, rule `body>section.page` đã luôn ghi đè `max-width` của theme (1280/1360), nên các `max-width` đó vô tác dụng. Tôi xoá chúng và cho rule đó dùng `--page-max`. Trang Cài đặt có thẻ rộng 620px, 920px và không giới hạn lẫn lộn; giờ đều tối đa 920px.
- **Chiều cao nút và ô nhập:**
  - Trước đây: nút ~31px, ô text ~35px, select ~33px. Theme Apple ép ô nhập padding 9px nên cao ~37px.
  - Giờ nút và ô nhập một dòng cao 34px, nút nhỏ 28px. Ô nhập và select dùng chung cỡ chữ 13px.
  - Rule này đặt trong khối style nạp sau theme nên áp dụng cho cả 3 theme.
  - Không đổi các select nhỏ trong khung chat (`.settings`, `.turnopts`), vì chúng cố ý gọn.
- **Bộ nhớ đệm theme:** file theme bị trình duyệt cache 1 ngày, nên tôi đổi `?v=2` thành `?v=3` để trình duyệt tải CSS mới.
